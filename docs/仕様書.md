# データ取込・按分・CSV変換 仕様書

> 現在は **実データの様式が未確認のため、架空の様式で実装** しています。実データ入手後に
> 「8. 実データ適用時の調整箇所」を見直してください。

## 1. 処理の流れ

```
利用明細PDF ──②読取──┐
管理台帳Excel ─①取込─┼─③照合─④按分─⑤出力─→ 費用振替CSV / 集計Excel / エラーExcel
給与按分Excel ───────┘                ↑
              修正ファイル(⑥画面で入力) ┘ 実行のたびに当て直す
```

## 2. 入力データ

### 2.1 管理台帳（`管理台帳_*.xlsx`）
シート「カード台帳」

| 列 | 必須 | 内容 |
|---|---|---|
| カード番号 | ○ | ハイフン・空白・全角は自動で除去して照合 |
| 施設コード | ○ | 施設マスタに存在すること |
| 施設名 |  | 施設マスタの名称を優先 |
| 区分 | ○ | `施設` / `AM` / `アドバイザー` |
| 社員番号 | AM・アドバイザーは○ | 給与按分資料との照合キー |
| 利用者 / カード名義 |  | カード名義はPDFの名義と照合（不一致は要確認） |
| 有効開始日 / 有効終了日 |  | 空欄は期限なし。**対象月と重なる行だけを使う** |

カードの利用者・施設が変わったときは、**旧行に有効終了日を入れ、新しい行を追加** します（履歴を残す）。
シート「施設マスタ」: 施設コード・施設名・部門コード（部門コードはCSVの借方部門）。

### 2.2 利用明細PDF（`利用明細_*.pdf`）
文字が埋め込まれたPDFを想定。読み取る行:

| 行 | 例 |
|---|---|
| 請求合計 | `ご請求合計金額 ¥3,462,048` |
| カード見出し | `カード番号 4980-xxxx-xxxx-xxxx 名義 サクラカン 1` |
| 明細行 | `10/04 SS中央通り 軽油 31.64L 4,714` |
| カード小計 | `カード小計 20,944` |

### 2.3 給与按分資料（`給与按分_*.xlsx`）
シート「按分」: 対象月（YYYY-MM、空欄は毎月共通）・社員番号・氏名・按分先施設コード・按分割合（%）。
1人につき按分先の数だけ行があり、割合の合計が100であること。

## 3. 照合・集計ルール
- キーは正規化したカード番号（数字16桁）
- 区分`施設`: 台帳の施設に全額を計上（直接）
- 区分`AM`・`アドバイザー`: 社員番号で給与按分資料を引き、按分（4章）
- エラーのあるカードは按分・CSVに含めず「保留」とし、保留額を整合性チェックに表示

## 4. 按分・端数処理
**最大剰余法**: 金額×割合を1円未満切り捨て → 配り残しを端数の大きい施設から1円ずつ配る（同じなら資料の上の行）。
按分後の合計は必ず元の金額と一致します（自動テストで2,000パターン確認）。
例: 10,000円を 33.33% / 33.33% / 33.34% → 3,333 / 3,333 / 3,334

※ 既存の業務ルール（例: 端数は最も割合の大きい施設に寄せる）が異なる場合は `src/allocator.py` の `split_amount` を変更します。

## 5. 費用振替CSV
- 文字コード Shift_JIS（cp932）、改行 CRLF、1施設1行（同じ施設の直接分と按分受入分は合算）
- 借方: 車両費／各施設の部門コード、貸方: 車両費／本部（000）、伝票日付は対象月末日
- 列・勘定科目・摘要は `config.yaml` の `journal` で変更可能

## 6. 整合性チェック（必須）
次がすべて成り立たないとCSVを出力しません。

1. PDF請求合計 ＝ 明細読取合計
2. 明細読取合計 ＝ 按分前合計 ＋ 保留金額
3. 按分前合計 ＝ 按分後合計 ＝ CSV借方合計 ＝ CSV貸方合計
4. 「エラー」が0件

## 7. エラーコード

| コード | 重要度 | 内容 | 画面での修正 |
|---|---|---|---|
| L001 | エラー | 台帳の必須項目が空欄 | カード情報を指定 |
| L002 | エラー | 同じカードが同じ期間に重複 | 台帳を修正 |
| L003 | エラー | 施設コードが施設マスタにない | カード情報を指定 |
| L004 | エラー | 区分が想定外 | カード情報を指定 |
| P001 | エラー | PDFの行を読み取れない | 金額を入力 |
| P002 | エラー | カード小計と明細合計が不一致 | 金額を入力 |
| P003 | エラー | 請求合計と読取合計が不一致 | PDFを確認 |
| P004 | エラー | 請求合計の行が見つからない | PDFの様式を確認 |
| P005 | 要確認 | AIが読み取った行（小計と一致済み） | 原本と見比べる |
| M001 | エラー | 台帳にないカード | カード情報を指定 |
| M002 | エラー | 台帳にあるが対象月は有効期間外 | カード情報を指定 |
| M003 | 要確認 | PDFと台帳のカード名義が違う | 台帳を確認 |
| M004 | エラー | 按分対象者なのに社員番号なし | カード情報を指定 |
| M005 | 情報 | 有効なのに当月利用なし | 不要 |
| A001 | エラー | 按分資料に該当者なし | 按分を入力 |
| A002 | エラー | 按分割合の合計が100%でない | 按分を入力 |
| A003 | エラー | 按分先施設が施設マスタにない | 按分を入力 |
| C001 | エラー | 合計が一致しない（不具合） | 開発担当へ連絡 |

## 8. AI読取補助（Claude API）
- ルール（正規表現）で読めなかった明細行だけを Claude（`claude-opus-5-5`）に送り、日付・給油所・品目・数量・金額をJSON形式で受け取る
- **送るのは行の文字列だけ**。カード番号・名義・施設名は送らない（行IDで対応づけ）
- AIの値は、**カード小計と一致したときだけ採用**し、「要確認(P005)」として担当者が原本確認
- 一致しない・APIキーなし・通信エラーのときは、AIなしの場合と同じくエラー(P001)として手入力に回す
- 送受信内容は `data/logs/ai_requests.jsonl` に記録
- 安全判定でAIが応答を断った場合に、サーバー側で別のモデルに切り替える設定（fallbacks）を有効化済み
- `config.yaml` の `ai.enabled: false` または画面のスイッチでAIを完全に止められる

## 9. セキュリティ
| 項目 | 対策 |
|---|---|
| 保存場所 | 入力・出力・修正・ログはすべて `data/` 配下。**このフォルダは OneDrive 同期下にあるため、実データ運用時は同期対象外のフォルダ（社内ファイルサーバーのアクセス制限付きフォルダ等）へ移す**。`config.yaml` の `paths` で変更可能 |
| アクセス | 画面は `localhost` のみで待ち受け（社内LANからも開けない）。利用者は経理担当者のPCに限定 |
| 外部送信 | Claude API へは読めなかった行の文字列のみ。カード番号・氏名は送らない。AIを止めれば外部送信ゼロ |
| APIキー | 環境変数で管理し、ファイルやコードに書かない |
| 改ざん防止 | 元データは書き換えない。修正は担当者名・日時付きで修正ファイルに履歴として残る |
| 共有 | `.gitignore` で `data/` を除外し、ソースコード共有時に実データが混ざらないようにする |
| 保管期間 | 出力物は会計帳票として社内規程の期間保管。不要になった入力PDFは削除 |

## 10. 実データ適用時の調整箇所
1. `src/pdf_reader.py` の `PATTERNS`（実PDFの行の書式に合わせる）。スキャン画像のPDFならOCR、またはAIにPDFページ画像を渡す方式を追加
2. `config.yaml` の `ledger.columns` / `allocation.columns`（既存Excelの列名）
3. `config.yaml` の `journal`（既存の振替CSVの列・科目コード・文字コード）
4. 端数処理ルール（4章）
5. 区分の名称（`ledger.allocation_categories`）
